# Результаты canvas-bench

Методика: 5 циклов «открыть/закрыть», фазы open/close-anim, пороги 33/50/100мс
(как в `tools/perf-anim-ab.js`). Набор `light`: `dom-blur` (baseline лаунчера),
`dom-noblur` (контроль), `c2d-live` (ctx.filter каждый кадр), `c2d-baked`
(blur запечён), `webgl-live` (2-проходный шейдерный блюр по FBO).
Набор `heavy` — DOM-сцена со сложностью лаунчера (панель min(940,95vw),
element-filter blur(14px) в keyframes, 7 внешних блюров + V22, news-away):
`hv-full` / `hv-baked` / `hv-smooth` / `hv-noblur` / `hv-full-nov22`
(см. тяжёлый замер ниже; JSON: `heavy-home-pc.json`).

Панель 604×460, blur 24px, WebGL = ANGLE D3D11 (настоящая GPU, не SwiftShader).

## home-pc — heavy-сцена (DOM сложности лаунчера, Intel HD 4000)

Окно 1366×643, dpr 1, панель 940×553, blur 24px, 5 циклов.
Сцена воспроизводит анимации лаунчера: keyframes settingsRise/Sink
(scale 1.08 + opacity + element-filter blur(14px), 0.4s), навигация
blur(12px), 7 внешних стеклянных элементов с V22 (гашение на 550мс),
язычок новостей news-away. Тайминги классов — из openSettings/_closeWithAnim.

| вариант | avg | p50 | p95 | max | >33мс | open-anim avg | кадров |
|---|---|---|---|---|---|---|---|

| hv-baked (идея №1) | 16.7 | 17 | 17 | 31 | **0** | 16.6 | 420 |

У hv-full/v nov22 меньше кадров (378/373 против ~420 у остальных) —
это потерянные кадры во время анимации.

## dev-машина (16 ядер), Chromium 158, --disable-gpu, окно 1280×800

Все 5 вариантов: avg 16.6–16.8, 0 кадров >33мс (vsync-потолок).
dom-blur чуть выше: max 25.7 против ~18.5 у остальных.

## Выводы

1. **Живой blur в canvas2D (ctx.filter) — провал на слабой машине:**
   77 кадров с джанком, open-anim 36мс среднее (против 16.6 у всех).
   Не использовать пересчёт блюра на каждый кадр в canvas.
2. **DOM+backdrop-filter на простой сцене упирается в vsync и на HD 4000**
   (0 джанка) — сам по себе backdrop-blur панели 604×460 для неё дёшев.
   Тормоза лаунчера — не в одном этот блюре, а в совокупности (внешние
   блюры, анимация filter:blur() на панели, ререндер контента — см. фикс
   V22 в main).
3. **Запечённый canvas-blow и шейдерный WebGL не хуже DOM** (оба в vsync),
   но и не лучше — на этой сцене выигрыша ноль. Их смысл проявится только
   если живой backdrop станет дорог (сцена тяжелее: больше блюров/слоёв).
4. **Сцена стенда легче реального лаунчера** — прямые числа «лаунчер vs
   canvas» стенд не даёт. Для них нужен либо утяжелённый стенд (анимация
   filter:blur() на панели + движущийся внешний слой), либо замер самого
   лаунчера на home-pc.

## Выводы (heavy, идея №1 — запечённый блюр)

1. **Гипотеза подтверждена: `hv-baked` стоит как «ничего».** 16.7мс avg /
   0 рывков — ровно уровень пола (`hv-noblur`) и `hv-smooth`, то есть
   запечённый фон-блюр даёт стекло с первого кадра бесплатно. При этом
   `hv-full` (живой backdrop всю анимацию) — 18.5мс, 14 рывков, max 52мс
   и 378 кадров вместо 420 (потерянные кадры).
2. **V22 помогает, но не решает:** `hv-full-nov22` — 18 рывков против 14
   у `hv-full`. Внешние блюры — вторичная статья расходов; главный —
   живой backdrop + element-blur самой панели 940×553 на каждом кадре.
3. **`hv-baked` ≈ `hv-smooth` по цифрам, но лучше по виду:** smooth во
   время полёта показывает острый фон (блюр возвращается переходом 0.2с
   после анимации), baked — стекло с первого кадра. Это то, что просили
   вернуть («блюр виден с первого кадра») без цены режима full.
4. **Сценарий переноса в лаунчер:** на время open/close вместо
   `backdrop-filter` панели и навигации — заранее запечённая копия обоев
   (canvas2D один проход при старте/смене обоев), element-blur остаётся
   (он дешёвый без live-backdrop — см. smooth), V22 и news-away уже
   сделаны в main. Ожидаемый эффект: full 27.9мс/93 → уровень smooth.
5. Стенд всё ещё легче реального лаунчера (18.5 против 27.9 у full в
   собранном приложении) — но порядок и разрыв между режимами те же.

## Как повторить

```bash
node tools/canvas-bench/build-standalone.js   # собрать standalone.html
node tools/canvas-bench/run.js 5              # у себя (CHROME_EXE=...), heavy
node tools/canvas-bench/run.js 5 light        # light-набор
node tools/canvas-bench/run.js --serve        # сервер для встроенного браузера
```

`standalone.html` — автономный файл (обои base64), открывается двойным
кликом, кнопка «Запустить тест» + таблица на странице.
