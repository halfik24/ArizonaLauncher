# IDEA.md — Arizona RP Launcher v2 (для агента)

Краткая карта проекта, чтобы при входе в репозиторий было понятно, что здесь происходит.
Детали состояния/планов — в [HANDOFF.md](HANDOFF.md), публичное описание — в [README.md](README.md).

## Что это

Лаунчер для GTA San Andreas Multiplayer **Arizona RP** (СНГ-сервера). Текущая версия —
**v2.0.0-rc1-new**, полностью переписанная на **Rust + Tauri 2** с Python-версии v1
(исходники старой версии лежат в `old_python/`, там же оригинал README от worteng).
Платформа — только Windows 10/11 x64 (WebView2), установщик NSIS без прав админа.

## Архитектура

```
src/                    фронтенд — ОДИН файл index.html (~16к строк, vanilla JS + CSS)
  ├─ tauri-bridge.js    мост: позиционные вызовы pywebview.api.* → tauri invoke() с
  │                     именованными camelCase-аргументами (генерируется tools/gen-bridge.js
  │                     из сигнатур launcher.rs). Фронт писался под pywebview и почти не
  │                     менялся — вызывает window.pywebview.api.X(...) как раньше.
  └─ lucide.min.js      иконки
src-tauri/src/
  ├─ main.rs            точка входа: логирование, tray, регистрирует ~95 команд
  ├─ launcher.rs        ВСЯ бизнес-логика (~4700 строк): запуск игры, патчи,
  │                     каталоги модов, серверы/новости, обои, профили, окно/трей...
  ├─ config.rs          LauncherConfig → <Documents>/ArizonaLauncher/config.json
  ├─ util.rs            пути, лог-файл
  └─ game_update/       движок установки/обновления/починки игры (модуль отдельный,
      │                 порт official az-proto лаунчера)
      ├─ manifest.rs    парсер game.json (дерево → плоский список, variant future/default)
      ├─ verify.rs      сверка локальных файлов с манифестом → план (Mkdir/Delete/
      │                 DateFix/Download), параллельный MD5 (до 8 воркеров)
      ├─ downloader.rs  reqwest: манифест + файлы, фоллбэк main→reserve CDN
      ├─ engine.rs      оркестрация Check/Apply/Repair, события в колбэк, отмена
      └─ state.rs       кэш md5-хэшей (game_update_state.json)
tools/                  dev-скрипты: gen-bridge.js, perf-*.js, cdp.js (проверки через CDP)
.agent/                 рабочая папка агента (не в git): скриншоты окна, UI-проверки
```

**Ключевой принцип:** фронтенд — почти нетронутый Python-код из v1, адаптированный
только бриджем. Поэтому в `index.html` всё ещё есть `pywebview.api`, проверки
`if (window.pywebview.api.X)` и т.п. Не «чищить» это без нужды.

## Основные подсистемы (бэкенд, launcher.rs)

- **Запуск игры** (`start_game`): два режима — `native` (сами запускаем gta_sa.exe
  с аргументами) и `air` (через ArizonaLauncher*.exe, поддерживается только Air v8).
  Аргументы: память, CDN (формат `x,x,x`, валидируется), CEF/автологин и десятки
  параметров (`LaunchParams` в config.rs). Пишет реестр SAMP (ник, память).
- **Авто-поиск игры** (`auto_detect_paths`): реестр (Uninstall-ключи со словом
  «Arizona») + скан корней дисков (папки с «arizona», дедлайн 5с), в spawn_blocking.
- **Установка/обновление/починка игры** (`game_update/`): манифест `game.json` с CDN
  `https://pc.az-ins.com/release` (резерв `https://arz-pc.react-group.tech/release`),
  файлы по `{cdn}/game/{rel}`. `game_path` = путь до `gta_sa.exe`, папка манифеста =
  родитель. Качка в `.part` → переименование, докачка с места обрыва (Range),
  лимит скорости (токен-ведро, `game_update_limit_mb` в настройках), MD5 после
  качки, кэш хэшей, отмена флагом (не удаляет .part).
- **Патчи (ArizonaPatches)**: редактор с диффом, бэкапы (авто, до N), импорт/экспорт,
  пресеты и схема — качаются с GitHub (репо halfik24/ArzLaunchRepo), без перевыпуска
  лаунчера.
- **Каталоги** (тоже с GitHub): луаскрипты MoonLoader (установка/включение/удаление),
  библиотеки (mimgui и пр.), «дополнения» (DxVK и пр.). Обновляются извне.
- **Серверы и новости**: список серверов с онлайном (иконки кэшируются на диск,
  ETag/Last-Modified), новости лаунчера с отметкой прочитанного.
- **UI-инфраструктура**: свои рамка окна (custom/system), трей (левый клик — показать,
  закрытие в трей), обои (встроенная коллекция + свои), профили с автосохранением
  настроек, статус-бар, монет-палитра из обоев (Monet), status-bar, лайтбоксы.

## Хранилище пользователя

Всё в `<Documents>/ArizonaLauncher/`:
- `config.json` — конфиг (ник, сервер, game_path, launch_params, launcher_settings,
  профили, прочитанные новости);
- `launcher.log` — диагностика (>2 МБ сдвигается в `.old`);
- `game_update_state.json` — кэш md5;
- кэш иконок серверов и пр.

## Фронтенд (src/index.html)

Один самодостаточный HTML: разметка, стили, весь JS. Основные «экраны»:
онбординг-визард (first-launch: шаги — стена, поиск/установка игры, обои, запуск
метод), главный интерфейс (кнопка Play, профили, новости, статус-бар), настройки
(множество вкладок: launch params, патчи, каталоги, обои, рамка окна, отладка),
модалки (подтверждение, установка, лайтбокс, редактор патчей/CRE и т.д.).
Классы в JS часто с префиксами: `_fl*` — first-launch, `_cso*` — редактор серверов,
`_lb*` — лайтбокс, `_mods*` — модалки.

## Dev-цикл

```bash
npm install
npm run dev      # tauri dev: backend пересобирается сам, фронт — Ctrl+R в окне
npm run build    # релиз + NSIS-установщик (src-tauri/target/release/bundle/nsis/)
cd src-tauri && cargo test   # тесты бэкенда (~32 #[test], в основном launcher.rs + game_update)
```

CDP-тесты UI: временно добавить `--remote-debugging-port=9222` в
`additionalBrowserArgs` в `src-tauri/tauri.conf.json` (**убрать перед коммитом!**),
затем `node tools/cdp.js "<JS-выражение>"`; скриншоты окна — `.agent/flcap.ps1`
(окно должно быть в фокусе, иначе WebView2 отдаёт старые кадры).

## Конвенции и правила

- Общение — кратко, по-русски. Комментарии в коде и UI-строки тоже на русском.
- Локальные коммиты **без пуша**, история не переписывать.
- Стиль коммитов: `тип(область): суть` — напр.
  `game-update: докачка .part с места обрыва...`, `ui: ...`, `feat(onboarding): ...`.
- Версия синхронизируется в `package.json`, `src-tauri/tauri.conf.json`,
  `src-tauri/Cargo.toml` (сейчас 2.0.0-rc1-new).
- Секретов/переменных окружения в репе нет; внешние сервисы — только публичные CDN
  и GitHub-репо каталогов.

## Известные подводные камни

- `select_game_path` (launcher.rs) для пустой папки возвращает маркер
  `{code:'EMPTY_FOLDER', folder}`, а не ошибку — фронт спрашивает «Установить игру
  сюда?» и вызывает `install_game_api(folder)`.
- `launcher_settings` использует `#[serde(flatten)] extra` — незнакомые ключи
  настроек сохраняются целиком (как в легаси), не отбрасываются.
- Настройка «Проверять обновления игры при запуске» лежит в extra настроек.
- В `main.rs` окно создаётся `visible: false` и показывается после применения рамки —
  чтобы не мигала системная рамка.
- Закрытие при custom-рамке прячет окно в трей (prevent_close); второй экземпляр
  не запускается (tauri-plugin-single-instance) — показывает окно первого.
- Встроенные обои лежат в `wallpapers/` в КОРНЕ репо (не в src/) — только как
  bundle.resources, без вшивания в бинарник через frontendDist.
- **CSP держим `null`**: CSP в tauri.conf.json блокирует инъекцию IPC-бриджа
  Tauri в release (dev не применяет CSP — дефект не виден локально):
  pywebview-ready не наступает, init фронта не выполняется, UI «разваливается»
  (нативные select'ы поверх кастомных, мусорные панели видны). Вернуть
  hardening можно только с nonce/hash-подходом и обязательным релизным
  smoke-прогоном (cargo check это не ловит).
- Релизный exe в portable называется `Arizona RP Launcher.exe` (с пробелами) —
  в dev процесс `arizona-launcher.exe`; когда убиваешь процесс, проверяй оба
  имени (при single-instance новый экземпляр молча уходит, а окно показывает
  старый процесс — легко перепутать, что тестируешь).
